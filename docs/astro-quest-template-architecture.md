# Stardy · 可复制路径 · 模板架构设计

> 写于 2026-08-25 · 用户决策：**"先天文 → 再观鸟 → 再所有知识类可套用"**
> 这份文档把 `bp.md` 第 0 节定义升级为：**"Duolingo 化知识科普产品矩阵"** 而非单一 App。

---

## 0. 一句话重新定义

**Stardy 不是天文 App，是「Duolingo 化知识科普产品的可复用模板」。天文是第一条线，下一条线是观鸟，之后是蘑菇 / 植物 / 海洋生物 / 古典乐 / ...。**

天文主题的子品牌：**Stardy · 星旅**
未来观鸟主题的子品牌：**Stardy · 林间**（示意）

> 这把估值故事从「中国版天文 Duolingo · ¥2-3 亿」升级成「可复用的知识 Duolingo · ¥20-50 亿」。

## 1. 为什么"可复制"是更大的故事

### 1.1 单一天文的天花板
- 中国天文 / 观星 App 市场 ~¥3 亿
- 即使吃下 50% 份额也只 ~¥1.5 亿年收
- 资本市场对「小众 + 低 ARPU」没兴趣

### 1.2 模板化后能扩到的 TAM
| 主题 | 中国潜在用户 | 付费意愿 |
|---|---|---|
| 🪐 天文 | 3000 万 | 中 |
| 🐦 观鸟 | 2000 万 | **高**（望远镜/相机/旅行） |
| 🍄 蘑菇 | 1500 万 | 中 |
| 🌿 植物 / 花卉 | 4000 万 | 中 |
| 🐠 海洋生物 | 2000 万 | 中 |
| 🎵 古典乐 | 1500 万 | 高 |
| 🎬 电影鉴赏 | 5000 万 | 中 |
| 🏛️ 博物馆讲解 | 8000 万 | 中 |
| 🧠 心理学入门 | 6000 万 | 中 |
| ☕ 葡萄酒 / 咖啡 / 茶 | 3000 万 | **高** |

合计潜在用户 > 3 亿，付费意愿强的几个垂类都吃得上。

### 1.3 估值故事转变
- 之前：**「中国版天文 Duolingo」** → 估值 ¥2-3 亿
- 现在：**「Duolingo for Knowledge · 跨主题可复用模板」** → 估值 ¥20-50 亿
  - 对标：Duolingo Math/Music 把估值从 30 亿拉到 60 亿
  - 对标：可汗学院从"数学视频"扩到 K-12 全科，估值 30 亿

## 2. 当前架构的「可复制性」评估

基于刚才的代码扫描，**当前架构已经做到 60% 的解耦**，剩下 40% 是明确可改造的：

| 维度 | 现状 | 可复用度 |
|---|---|---|
| 内容 schema（Lesson/Question/Choice/TeachCard） | `lib/astro/types.ts` 已定义 | ✅ **100% 可复用** |
| UI 组件（StarPath / QuizCard / FeedbackSheet / LessonRunner） | 通用 | ✅ **100% 可复用** |
| 通用游戏机制（XP / 连胜 / 徽章 / 3 星 / 反馈） | `game-store.tsx` 通用 | ✅ **100% 可复用** |
| Onboarding（4 步欢迎 / 选目标 / 选强度 / ready） | 抽象 | ✅ **90% 可复用** |
| 设计 token 系统 | 已变量化（`.sk-*`） | ✅ **90% 可复用** |
| Bottom Nav / StatPill / AppShell | 通用 | ✅ **100% 可复用** |
| **主题包数据** | ❌ 硬编码在 `content.ts` | ⚠️ **需抽离到 DB** |
| **主题色 / 品牌** | ❌ 硬编码在 `globals.css` | ⚠️ **需动态化** |
| **主题专属模块**（"今晚看什么"） | ❌ 写在产品里 | ⚠️ **需可插拔** |
| **品牌资产**（mascot-star.png / 海报 / 字体） | ❌ 硬编码 | ⚠️ **需主题包携带** |
| **i18n 词条** | 部分主题词硬编码 | ⚠️ **需主题包携带** |

## 3. 模板化架构设计

### 3.1 三层模型
```
┌─────────────────────────────────────────────┐
│           Theme Pack（主题包）              │
│  ───────────────────────────                │
│  · meta: id / name / tagline / icon         │
│  · brand: mascot / palette / decorSeed      │
│  · content: Track[] → Lesson[]              │
│  · features: ['daily','tonight',...]        │
│  · moduleSlots: { homeHero, sidebar, ... }  │
│  · i18n: 部分主题相关词条                    │
│  · seo: 长尾词 / 海报 / 视频脚本            │
└─────────────────────────────────────────────┘
                    ↓ 注入
┌─────────────────────────────────────────────┐
│        Generic Shell（通用骨架）             │
│  ───────────────────────────                │
│  · Layout / Splash / Onboarding / Nav       │
│  · StarPath / QuizCard / Feedback / Runner  │
│  · Daily / Leaderboard / Account            │
│  · GameStore（跨主题共享 XP/连胜/徽章）     │
│  · ThemeProvider（动态注入 palette + decor） │
└─────────────────────────────────────────────┘
                    ↓ 部署
            N 个 App 站点 / N 个小程序
            （按主题分发 / 共用一个壳）
```

### 3.2 主题包数据模型（要进数据库）
```ts
interface ThemePack {
  id: string;                  // "astronomy" | "birds" | "mushroom"
  name: Localized;             // "星旅" / "林间" / "采蘑菇"
  tagline: Localized;
  icon: string;                // emoji
  status: 'draft' | 'live' | 'archived';

  brand: {
    mascot: { src: string; alt: Localized };
    palette: {
      primary: string;         // hex
      accent: string;
      surface: string;
      nightStar: string;       // 装饰元素颜色
    };
    decorSeed: 'stars' | 'leaves' | 'mushrooms' | 'waves';
    fonts: { heading: string; body: string };
  };

  features: Array<
    | 'daily-question'          // 通用
    | 'tonight'                 // 天文专属
    | 'sightings-log'           // 观鸟专属
    | 'foraging-map'            // 蘑菇专属
    | 'collection'              // 通用（收集卡）
  >;

  tracks: Track[];             // 已存在
  seo: { longTails: string[]; poster: string };
}
```

### 3.3 主题切换机制（用户视角）
- **首次进入**：Onboarding 第 1 步变成「选一个主题入门」（3–4 个缩略图）
- **已登录**：首页左上角放主题切换器（小图标 + 当前主题名）
- **跨主题**：XP / 连胜 / 徽章墙 **全局共享**（让切换有积累感）
- **进度**：每个主题独立进度条（学完天文再开观鸟，不冲突）

### 3.4 主题专属模块的"插槽"
通用壳保留几个固定插槽，主题包填内容：

| 插槽 | 通用组件 | 天文填什么 | 观鸟填什么 | 蘑菇填什么 |
|---|---|---|---|---|
| HomeHero | `<HomeHero>` | "今晚看什么" | "今天哪里有鸟" | "最近哪里能采" |
| DailyExtra | `<DailyExtra>` | 月相 / 流星雨 | 今日可见鸟种 | 当季常见蘑菇 |
| AchievementTag | `<Collection>` | 88 星座 | 500 种鸟 | 200 种可食蘑菇 |
| LessonFinishModal | `<LessonFinish>` | "今晚 22:00 看 X" | "明天早起 X 鸟过境" | "本周 X 蘑菇季" |

## 4. 第一个复制目标：观鸟（Birds）

套用同一套架构的最小修改清单：

### 4.1 主题包
| 项 | 内容 |
|---|---|
| id | `birds` |
| 中文名 | **林间** |
| tagline | "认识你家窗外的鸟，从麻雀到戴胜" |
| 主色 | 森林绿 `#2D6A4F` + 暖橙 `#E76F51` |
| 装饰 | 叶片点阵 + 羽毛纹 |
| mascot | 一只卡通小鸫，戴观鸟帽 |

### 4.2 内容骨架（80–100 关 / 4 阶段）
| 阶段 | 单元 | 微节 |
|---|---|---|
| A 入门 | 鸟的身体 | 体长 / 喙型 / 翅形 / 尾羽 / 羽色 |
| A 入门 | 怎么看鸟 | 用眼 / 用耳 / 用望远镜 / 记录方法 |
| B 城市常见 | 麻雀 / 喜鹊 / 乌鸫 / 白头鹎 / 珠颈斑鸠 / 八哥 / 楼燕 | 各 1 关 |
| B 城市常见 | 行为 | 洗澡 / 觅食 / 鸣叫 / 求偶 |
| C 林鸟 | 啄木鸟 / 山雀 / 莺类 / 鹟类 / 鸫类 | 各 1 关 |
| C 林鸟 | 鸣声识别 | 柳莺鸣声 / 山雀联络 / 夜鹰 |
| D 进阶 | 迁徙 | 春秋迁徙路线 / 猛禽迁徙通道 |
| D 进阶 | 季节行为 | 繁殖羽 / 冬羽 / 换羽 |
| D 进阶 | 找鸟地图 | 城市绿地 / 国家级观鸟胜地 |

### 4.3 主题专属模块
- **「今天哪里有鸟」**：用 eBird API（免费）显示用户附近 30 天高频鸟种 + 公园推荐
- **「我的鸟种记录」**：UGC 照片上传 + AI 识别（iNaturalist / Merlin API）
- **季节性徽章**：春迁 5 月 / 秋猛 10 月

### 4.4 复用率估算
- 通用 UI 组件：**100% 复用**
- 通用 game-store / 主题 store：**100% 复用**
- 内容 schema：**100% 复用**
- 设计 token：**90% 复用**（只换色和装饰）
- Onboarding：**90% 复用**（"观鸟入门"替换"观星入门"）
- 主题专属模块：**0% 复用**（需要新写）

### 4.5 工时估算
- **数据建模 + token 切换**：1 人周
- **第二个主题包数据**（80 关内容）：1 人月
- **"今天哪里有鸟"模块 + Merlin 对接**：1 人月
- **总计**：~2.5 人月让观鸟主题独立上线

> 这就是"模板可复用"的真实价值——**第二个主题上线成本只有第一个的 30%**。

## 5. 实施步骤（让模板真正能复用）

### 5.1 第 1 步：抽象主题 token（Week 1）
- 把 `globals.css` 里的 `--primary / --accent / --cream / --night-*` 移到 `data-theme-palette` 属性
- 新增 `<ThemeProvider palette={currentTheme.palette}>` 包裹 AppShell
- 验证：light/dark 切到 forest/dusk 主题后整套 UI 跟着换

### 5.2 第 2 步：内容进数据库（Week 1-2）
- `themes` 表 + `tracks` 表 + `lessons` 表 + `questions` 表
- 把现有 `content.ts` 数据写一个 migration 灌进去
- 加一个 `useContent(themeId)` hook（取代静态 import）

### 5.3 第 3 步：主题包加载（Week 2）
- 新增 `/api/themes/[id]` GET 接口
- 前端根据 URL 参数或本地存储切换主题
- 主题包数据缓存到 localStorage

### 5.4 第 4 步：通用模块 vs 主题模块分离（Week 2-3）
- 把"今晚看什么"从产品代码移到 `themes/astronomy/module.ts`
- 通用模块用 `slot` 或 `module.component` 注入
- 预留观鸟 / 蘑菇的"主题模块"占位文件

### 5.5 第 5 步：动态 Onboarding（Week 3）
- Onboarding 的"目标"改成"主题"，从 `themes` 表里取
- 每个主题自己写欢迎文案 + 卖点

### 5.6 第 6 步：第一个非天文主题上线（Week 4-10）
- 选观鸟作为第二个主题，验证模板
- 同时做品牌资产：mascot / 海报 / SEO 词
- 1 个内容 + 1 个工程 + 1 个鸟类学顾问

### 5.7 退出标准（重要！）
**模板可复用的硬指标：第二个主题（观鸟）从立项到上线 ≤ 10 周、≤ 2.5 人月。如果做不到，就是抽象层不到位，要回头改架构而不是改内容。**

## 6. 商业模式（结合用户"先免费"决策）

### 6.1 阶段一（现在 → 6 个月）：完全免费
- 所有主题、所有功能免费
- 唯一货币化：**品牌联名 / 内容赞助**
  - 自然博物馆、国家天文台、鸟类协会、世界自然基金会
  - 形式：内容冠名 + 推送联名 + 线下活动

### 6.2 阶段二（M4+）：单主题订阅
- 默认一个主题终身免费（如天文）
- 第 2、3... 个主题订阅：**¥18/月 / ¥168/年 / ¥328 终身**
- 转化点：第一个主题学完第 1 章 → 解锁"想学更多？"入口
- 比 Duolingo 友好：Duolingo 是单 App 内订阅；我们按"主题"订阅降低单次付费门槛

### 6.3 阶段三（12+ 月）：横向扩
- 5+ 个主题上线后：
  - "Stardy 全主题包" ¥698/年
  - 学校 / 自然教育机构企业版
  - 内容授权给自然博物馆 / 文旅景区

### 6.4 终极商业模式
**"模板 + 主题包" SaaS：**
- 把这套架构授权给：
  - 出版社（人教 / 商务印书馆 → 学科版 Stardy）
  - 国家公园 / 5A 景区（专属主题）
  - 教育机构（STEAM 学校联盟）
- 收入：授权费 + 主题包销售收入分成

## 7. 关键判断：什么时候开第二个主题？

| 信号 | 含义 | 动作 |
|---|---|---|
| 天文主题 7 日留存 ≥ 25% | 第一条线模型成立 | **立即开第二条（观鸟）** |
| 天文主题 7 日留存 < 15% | 第一条线模型还没跑通 | 优化天文，暂缓复制 |
| 天文主题 DAU > 1 万 | 有现金流验证 | 可以并行做第二条 |
| 出现外部合作需求（如自然博物馆主动来谈） | 渠道端倒逼 | 优先做合作方要的主题 |

> 按用户当前决策（先免费、单条线验证），**预计 M1 末（2026 Q3 末）就有结论**：扩到 50 关 + 进度入库 + AI 错题后，看 7 日留存再决定是否复制。

## 8. 风险与对冲

| 风险 | 对冲 |
|---|---|
| 抽象过度，做"万能主题包"反而变笨重 | 第一个复制目标（观鸟）当验证；10 周上线为硬指标 |
| 主题切换反而分散单主题专注度 | 全局 XP / 徽章共享让切换有积累感；不让"切换"破坏心流 |
| 第二个主题找不到合适的内容顾问 | 用内容联盟 / 知乎 / B 站 KOL 合作众包；AI 草稿兜底 |
| 主题之间互相抢用户注意力 | 主线主题做完第 1 章才推第二个主题；不让"尝鲜"破坏完成率 |
| 模板抽象不彻底导致改造成本失控 | 设硬指标：第二个主题上线 ≤ 10 周 |
