## 第一梯队 · 本周就能做（强 ROI）

### 1.1 把内容从 16 关扩到 50 关 + 真正分 5 阶段
- **R=5** · **工时=8h** · **依赖=无**
- 依据你 `pasted-text` 已经写好的 A/B/C/D/E 阶段 × 微节表，照着补 `content.ts`
- 顺手把 `trackId` 从 `"journey"` 拆成 `stargazing / solar / stars / cosmos / frontier` 5 个，顶部加 Tab 切换
- **解锁**：内容厚度达标，可投放到「天文爱好者」垂直社区做第一次内容型冷启动

### 1.2 把用户进度真正写到 PostgreSQL
- **R=5** · **工时=3h** · **依赖=已有 users 表**
- 新增 `user_progress`（user_id / lesson_id / stars / correct_count / best_at / attempts JSONB）
- 改 `completeLesson` 把进度 upsert 到 DB（用 Eazo `requireAuth` 拿 userId）
- **解锁**：跨设备进度同步 + 真排行榜的前提

### 1.3 错题讲解接 `appAi.chat`
- **R=5** · **工时=3h** · **依赖=已接 Eazo AI**
- 在 `feedback-sheet.tsx` 的「解释」文案下加「让 AI 老师再讲一遍」按钮
- 调 `appAi.chat({ model: "deepseek.v3.1", messages: [...] })` 流式输出，限 200 字
- 第一次失败 toast 提示「联系创作者补额度」（已写好）
- **解锁**：AI 价值显性化

### 1.4 把"主题"作为一等公民抽出来（**模板化的第一步**）
- **R=5** · **工时=12h** · **依赖=1.2 数据库**
- 新增 `themes` 表：`id / name_i18n / tagline_i18n / icon / palette_json / decor_seed / mascot_url`
- 把 `content.ts` 里的 tracks 全部迁到 `theme_tracks / theme_lessons / theme_questions` 表
- 新增 `useTheme(themeId)` hook，通用组件读主题
- 当前只有 `astronomy` 一个主题，但**架构先准备好**
- **解锁**：第二个主题（观鸟）可以并行开工；估值故事从单 App 升级为模板

### 1.5 主题色 / 品牌 / i18n 词条全部主题包化
- **R=5** · **工时=8h** · **依赖=1.4**
- 把 `globals.css` 的 `--primary / --accent / --cream / --night-*` 改成通过 `data-theme-palette` 属性注入
- 新增 `<ThemeProvider>` 包裹 AppShell，根据当前主题动态输出 token
- mascot 图片、装饰 dot 网格从主题包读取
- i18n 主题相关词条放进 `themes/[id]/i18n/`
- **解锁**：第二个主题（观鸟）从立项到上线 ≤ 10 周的硬指标才有希望达成

## 第二梯队 · 两周内做完（解锁模板复用）

### 2.1 通用模块 vs 主题模块插槽分离
- **R=4** · **工时=10h** · **依赖=1.4 / 1.5**
- 把"今晚看什么"从产品代码移到 `themes/astronomy/module.ts`
- 通用模块用 `slot` 或 `module.component` 注入
- 预留观鸟 / 蘑菇的"主题模块"占位文件
- HomeHero / DailyExtra / LessonFinish 各开一个 slot
- **解锁**：第二个主题只需要填内容，不用改通用代码

### 2.2 真排行榜 + 周赛季重置
- **R=4** · **工时=4h** · **依赖=1.2**
- 新增 `season_xp` 表（user_id / theme_id / season_id / xp / week_no）
- `/leaderboard` 用同段位（同 league）的人排；按主题分组 + 全局榜
- **解锁**：DAU → 7 日留存的可量化入口

### 2.3 知识图谱：节点可跳 / 支线可解锁
- **R=4** · **工时=12h** · **依赖=1.1 扩到 50 关**
- 引入「前置依赖」字段 `requires: string[]`
- 星图节点根据 `requires` 计算 locked / current / done
- 新增「跳级测试」（你 pasted-text 里已经设计好了：N×8 题 / 限时 40 秒 / 通过线 75%）
- **解锁**：从「单线」变成「知识图谱」

### 2.4 间隔重复 FSRS 算法
- **R=4** · **工时=8h** · **依赖=1.2**
- 引入 `fsrs` 库，给每个 user × lesson × theme 算 stability / difficulty / next_review_at
- 每日一题从「固定 1 题」改成「按 FSRS 选最该复习的 1 题」
- **解锁**：长期留存 + 错题率自然下降

## 横向脑暴 · 容易忽略的边角

### B.1 数据埋点
- 不接埋点谈增长就是耍流氓
- 接 `posthog` / `umami` / 自建 Eazo 端点
- 关键事件：`lesson_start / lesson_complete / theme_switch / question_answer / ai_explain_click / share`

### B.2 A/B 测试框架
- 内容侧（题干措辞 / 选项顺序）+ 激励侧（XP 倍率 / 主题切换时机）
- 用最轻的 `posthog feature flags` 或自写 hash bucket

### B.3 反作弊
- 排行榜作弊会摧毁留存
- 客户端：心跳 + 切屏检测 + 答题速度异常检测
- 服务端：题目下发时打 nonce + 答卷时限校验

### B.4 可访问性
- 屏幕阅读器 / 色弱模式 / 单手模式

### B.5 离线模式
- PWA + Service Worker 缓存内容
- 通勤 / 飞机 / 露营场景刚需

### B.6 法规
- 中国：青少年模式（≤ 40 分钟 / 单日）+ 内容审核
- 海外：COPPA / GDPR-K / App Tracking Transparency

### B.7 SEO 长尾
- 「今晚月相」「5 月观鸟攻略」零竞争
- 给每个微节配可被搜索引擎抓的网页版本（SSR + JSON-LD）

### B.8 主题专属模块的"AI 接入"
- 天文「今晚看什么」→ 用 `astronomy-engine`（离线计算）+ USNO 数据
- 观鸟「今天哪里有鸟」→ eBird API + Merlin AI 识别
- 蘑菇「最近哪里能采」→ iNaturalist API + 当地真菌协会
- 这些都是**主题专属**，但都能接 `appAi` 做包装
